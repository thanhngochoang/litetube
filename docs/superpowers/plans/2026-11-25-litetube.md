# LiteTube Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build LiteTube, a small Android app (< 10 MB per APK) that downloads YouTube videos and audio as MP3/M4A/MP4 and trims audio clips.

**Architecture:** A single `app` module. NewPipeExtractor resolves stream URLs. OkHttp downloads them in Range chunks. Android's built-in `MediaExtractor`/`MediaCodec`/`MediaMuxer` handle decoding, trimming and muxing. LAME 3.100, compiled with the NDK behind a thin JNI wrapper, encodes MP3. Finished files go into MediaStore. Pure logic lives in plain Kotlin classes with JVM unit tests. Media and native code get instrumented tests on an emulator or a device.

**Tech Stack:** Kotlin, Jetpack Compose + Material 3, NewPipeExtractor (JitPack), OkHttp, LAME 3.100 (C, CMake, NDK r28+), JUnit 4, OkHttp MockWebServer, AndroidX Test, GitHub Actions.

**Spec:** [`docs/superpowers/specs/2026-11-25-litetube-design.md`](../specs/2026-11-25-litetube-design.md) (Vietnamese). Read it before any task.

## Global Constraints

- Package / applicationId: `io.github.thanhngochoang.litetube`. App name "LiteTube".
- `minSdk 29`, `targetSdk 35`, `compileSdk 37` (the platform installed on this machine).
- ABIs: `arm64-v8a`, `armeabi-v7a`, built as **one APK per ABI** (ABI splits).
- APK size: target < 10 MB per APK; **CI fails above 15 MB**.
- No FFmpeg, no ExoPlayer/Media3, no analytics, no ads. Network hosts: YouTube (`*.youtube.com`, `*.googlevideo.com`, `i.ytimg.com`) and GitHub (`api.github.com`, `github.com`) only.
- LAME 3.100 is a shared library (`libmp3lame_jni.so`), LGPL, and must be **16 KB page aligned** (NDK r28+).
- MP3: CBR at 128 / 192 / 320 kbps, **default 192**. The UI says that 320 kbps cannot exceed the ~128 kbps source quality.
- Video: MP4 (H.264 + AAC) only, **max 1080p**, muxed without re-encoding.
- Output folders: audio → `Music/LiteTube/`, video → `Movies/LiteTube/`. Trimmed output is a new file named `<original name> (trim).<ext>`. Never overwrite an existing file.
- Download chunk size 10 MiB. Retry each chunk **3 times**, then fail.
- Fade in/out: linear, 2 s, clamped to half the clip length. MP3 only.
- Trim M4A export is offered **only when the source is AAC**. Otherwise MP3 only.
- Update check: `GET https://api.github.com/repos/thanhngochoang/litetube/releases/latest`, no token, at most once per 24 h.
- License: GPL-3.0 (already in the repo). The About screen lists LAME (LGPL-2.0), NewPipeExtractor (GPL-3.0) and OkHttp (Apache-2.0).
- UI strings live in `res/values/strings.xml`, in **Vietnamese** (the default locale). No hard-coded UI text.
- Git: the repo is already configured for user `thanhngochoang`. Push with `GH_TOKEN=$(gh auth token --user thanhngochoang) git push`, because the machine's default gh account is a different one.
- Commit messages follow Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Decisions made in this plan (the spec left them to the builder):** one download at a time (a sequential queue). No database: the library is a MediaStore query on the two LiteTube folders. Plain state-based navigation (no navigation-compose). Instrumented tests run locally, not in CI. Minimum trim length 0.5 s.

## Review Focus

1. **Very long videos (a 3-hour mix).** Transcoding and the waveform must stream PCM and never hold the whole track in memory. Tests: `WaveformAccumulatorTest.threeHourInputUsesFixedMemory` (Task 6) and `Mp3PipelineTest.streamsWithoutBufferingWholeTrack` (Task 7).
2. **Titles that make bad filenames** (`/`, `:`, emoji, 300 characters, `.`-only, a title that sanitizes to blank). Test: `FileNamesTest` (Task 9).
3. **Shared text with extra words around the link** ("xem cái này https://youtu.be/abc123def45?si=x hay lắm"), plus `shorts/`, `music.youtube.com`, `m.youtube.com`, and non-YouTube links. Test: `LinkParserTest` (Task 2).
4. **App killed mid-download** leaves temp files behind. They must be cleaned up on the next launch. Test: `TempCleanerTest` (Task 10).
5. **Trim edge cases:** start = end, end past duration, a fade longer than the clip, a clip shorter than 0.5 s. Tests: `PcmOpsTest.fadeClampedToHalfClip` (Task 6) and `TrimStateTest` (Task 12).
